# MediaForge v2 实施计划

Tauri 2 + Rust + Vanilla TS + Fluent 2，ffmpeg shared 作为随包引擎。
本文件是开工前的计划与技术验证记录，不含代码。

---

## 0. 摘要

71 种目标格式已经用真实 ffmpeg（n9.0.2 shared，v1 内置的那 9 个文件）**逐个跑过一遍**，
不依赖 v1 的结论：

- 66 个格式用「一次写对」的参数即可产出有效文件。
- 5 个格式需要特殊处理：4 个靠专用参数解决，1 个（MicroDVD）在当前 ffmpeg 构建里**没有编码器**，
  ffmpeg 无法产出该格式。
- 另有 1 个格式（SBV）在 v1 里是伪实现：用 srt 复用器 + `.sbv` 扩展名，产出的是 SRT 内容。

因此需要先定三件事（第 8 节），其余部分可以直接开工。

## 2. 与任务书不一致、必须调整的地方

### 2.1 `webLightTheme` 的导入路径要修正（对应坑 8）

任务书写的是 `setTheme(webLightTheme)`，但没有写 webLightTheme 从哪来。
web-components 3.2.1 不导出主题对象，只导出 `setTheme`：

```ts
import { setTheme } from "@fluentui/web-components/theme/index.js";
import { webLightTheme, webDarkTheme } from "@fluentui/tokens";
```

`@fluentui/tokens` 是 web-components 的直接依赖（`^1.0.0-alpha.24`），`type: module`，
exports 只有 `.`，Vite 可直接解析。建议显式装这个包并锁版本，避免 alpha 版本漂移。

### 2.2 MicroDVD 在当前 ffmpeg 构建里没有编码器

```
$ ffmpeg -h encoder=microdvd
Codec 'microdvd' is known to FFmpeg, but no encoders for it are available.
```

复用器存在（`-f microdvd` 可识别），但 10 个字幕编码器 × 有无 `-r` × `-c copy`，
全部失败，报 `Output file does not contain any stream`。
`-encoders` 清单里也没有 MicroDVD 行。这是工具链缺口，不是参数问题。

### 2.3 SBV 是伪实现

v1 的 `sbv` 定义复用 `srt` 复用器，产出 SRT 内容、存成 `.sbv`。实测确认：
内容形如 `1 | 00:00:00,500 --> 00:00:01,500`，这是 SRT 语法，SBV 应该是
`0:00:00.500,0:00:01.500`。界面上宣称支持 SBV 不成立。

### 2.4 需要专用管线的四种格式（均已实测通过）

| 格式 | 正确参数 | 失败过的写法 |
|---|---|---|
| ICO | `-vf scale=w=256:h=256:force_original_aspect_ratio=decrease,format=rgba -c:v png -frames:v 1 -update 1 -f ico` | `-c:v png -update 1` 不缩放（源大于 256）→ 0 字节；`scale=-1:256`（宽度自适应）→ 0 字节；`-pix_fmt pal8` → 失败 |
| DV | `-target pal-dv` 或 `-target ntsc-dv` | 手写 `scale=720:480,fps=30000/1001 + dvvideo` → `ff_frame_thread_encoder_init failed`；`-threads 1` 无效；720×576@25 手写可过但脆弱 |
| MXF | `-vf scale=1920:1080 -c:v dnxhd -b:v 120M -pix_fmt yuv422p -c:a pcm_s24le -ar 48000 -ac 2` | mpeg2video + 默认采样率 → `mxf: only 48khz is implemented`；补 `-ar 48000` 后 1280×720 / 1440×1080 / 1920×1080 / 720×576 均可过 |
| DTS | `-c:a dca -ar 48000 -ac 2 -b:a 768k -strict -2` | 裸 `-c:a dca` → `Nothing was written` |

### 2.5 进度解析的 Rust 陷阱

`out_time_us` 前两行是 `N/A`。C# 的 `long.TryParse` 返回 false 后静默跳过；
Rust 里 `"N/A".parse::<i64>()` 返回 `Err`，若把 Err 当异常抛出会导致任务在开始 0.3 秒时假失败。
解析器必须把非数字视作「本行无信息」并 continue。

### 2.6 取消必须清理残片

kill 后磁盘上留了 48 字节的 mp4。取消路径需要：kill → 等退出 → 删除目标文件（仅当本次任务创建）。
否则用户会在输出目录看到打不开的零字节目录项。

## 3. 架构

### 3.1 权威状态在后端

队列、任务状态、编码器能力、设置都放 Rust 侧（`AppState`），前端是视图。
命令返回变更后的快照，进度通过事件推送。理由：ffmpeg 是子进程，前端刷新/重载不该丢任务；
且参数构建与能力判断都在 Rust，前端重复一份必然漂移。

```
拖放 / 命令行 / 对话框
   ↓ add_paths(paths)
Rust: 展开目录 → ffprobe 每个文件 → 生成任务（含兼容性判定）→ 返回快照
   ↓ start()
Rust: 单 worker 线程按序执行 → 每个任务 spawn ffmpeg(-progress pipe:1)
   ↓ emit("task-progress", ...) / emit("task-finished", ...)
前端: store 合并快照与事件 → 定向更新 DOM
```

并发度默认 1（ffmpeg 自己已多线程），设置里可调 1–4。

### 3.2 模块划分（Rust）

| 文件 | 职责 | 形态 |
|---|---|---|
| `src-tauri/src/formats.rs` | 71 个格式定义（Id / 名称 / 类别 / 扩展名 / 复用器 / 编码器候选链 / 动图 / 备注） | 纯数据 + `&'static [Format]` |
| `src-tauri/src/args.rs` | 参数构建 | **纯函数**：`build_plan(req, probe, caps) -> Plan`，不碰进程与文件系统 |
| `src-tauri/src/compat.rs` | 4×4 兼容矩阵 + 拒绝原因 | 纯函数 |
| `src-tauri/src/progress.rs` | `-progress` 行解析 | 纯函数（带可变状态的小结构体） |
| `src-tauri/src/caps.rs` | `-encoders` / `-muxers` 文本解析 + 可用性判定 | 纯函数 |
| `src-tauri/src/probe.rs` | ffprobe JSON → `Probe` 结构 | 解析部分纯函数，调用部分隔离 |
| `src-tauri/src/paths.rs` | 定位随包 ffmpeg（resource_dir / dev 回退） | 有 IO |
| `src-tauri/src/settings.rs` | 设置读写（app_config_dir/settings.json） | 有 IO |
| `src-tauri/src/runner.rs` | 子进程驱动、进度采集、取消与残片清理 | 有 IO |
| `src-tauri/src/lib.rs` | Tauri 命令、AppState、事件、命令行参数 | 装配层 |

`args.rs` 不 `use std::process`、不 `use std::fs`，用一条测试断言这一点（源码层面检查）。

### 3.3 前端

```
src/
  main.ts          启动：注册组件、拿快照、挂载
  fluent.ts        18 个 define.js 的集中注册 + setTheme + 主题切换
  store.ts         单一 store（get/set/subscribe + 不可变更新）
  api.ts           invoke / listen 的类型化封装
  views/           队列列表、右侧参数面板、顶部工具条、底部状态栏
  styles.css       布局与少量 token 覆写
```

组件集（锁定这 18 个，体积贴近基线）：button, checkbox, dropdown, option, field, label,
progress-bar, slider, switch, text-input, radio-group, radio, dialog, divider, badge,
message-bar, tooltip, spinner。

### 3.4 关键配置

```jsonc
// src-tauri/tauri.conf.json（要点）
{
  "build": { "devUrl": "http://localhost:1420", "frontendDist": "../dist" },
  "app": { "windows": [{ "dragDropEnabled": true, "theme": null }] },
  "bundle": {
    "targets": ["nsis"],
    "resources": { "../vendor/ffmpeg/bin/*": "ffmpeg/" },
    "windows": { "webviewInstallMode": { "type": "embedBootstrapper", "silent": true } }
  }
}
```

`resources` 用 map 形式把 9 个文件摊到 `$RESOURCE/ffmpeg/`；运行时用
`app.path().resource_dir()` + `ffmpeg/ffmpeg.exe`。
开发期回退顺序：`MEDIAFORGE_FFMPEG` 环境变量 → `vendor/ffmpeg/bin/` → `PATH`。

   `vite`、`typescript`。

4. 写 `scripts/fetch-ffmpeg.ps1`：优先从 v1 路径复制，否则按 handoff 里的 URL 下载解压。
5. `AGENTS.md` + `.gitignore` + `LICENSE.txt`（MIT + ffmpeg GPL v3 声明与源码链接）。

**验收**：`npm run tauri dev` 出窗口；`vendor/ffmpeg/bin/ffmpeg.exe -version` 有输出。

### M1 三个 spike（约 45 分钟，全部在真机跑）

1. **Fluent 接入**：注册 18 个 `define.js` + `setTheme(webLightTheme)`，页面出现正常样式的按钮。
   同时验证 `webDarkTheme` 切换。
2. **主题跟随**：`matchMedia('(prefers-color-scheme: dark)')` 在 WebView2 里是否随系统变化；
   标题栏是否随 `window.setTheme()` 变深。若标题栏不变，退回 `DwmSetWindowAttribute(20)`
   （`windows` crate，约 20 行）。
3. **拖放**：`getCurrentWindow().onDragDropEvent()` 收到绝对路径；确认 HTML5 `drop` 事件在
   WebView2 里拿不到路径（预期拿不到，作为结论记录）。

**验收**：截一张浅色 + 一张深色的界面图，拖 3 个文件进窗口后路径出现在列表里。

### M2 Rust 核心（约 1.5 小时，TDD）

按依赖顺序，每步先写测试：

1. `formats.rs`：搬 71 个定义。测试：Id 唯一、扩展名带点、类别计数 20/15/29/7、
   每个视频格式至少 1 个视频编码器候选、每个音频格式至少 1 个音频候选。
2. `caps.rs`：解析能力清单。测试用 `tests/fixtures/encoders.txt` 真实输出快照
   （含前导空格行、`V..... = Video` 表头、`------` 分隔），断言解析出 233 个编码器且不含 `=`。
3. `progress.rs`：测试覆盖 `N/A`、`out_time_ms` 是微秒、`speed=1.5x`、`progress=end`、
   超 100% 回夹到 100。
4. `compat.rs`：16 组矩阵全测（含视频→字幕、音频→视频等 6 种拒绝）。
5. `args.rs`：按类别 + 特殊管线分支写测试，至少 25 条，断言参数数组逐项相等。
   覆盖面：拷贝模式、质量映射、码率、分辨率上限、元数据剥离、GIF 滤镜链、ICO/DV/MXF/DTS、
   无音轨时的 `?`、纯音频输出带 `-vn -sn -dn`。
6. `probe.rs`：一份真实 ffprobe JSON 快照 → 断言时长、流类型、分辨率、附件图识别。

**验收**：`cargo test` 全绿，其中纯单测 ≥ 40 条，耗时 < 2 s。

### M3 端到端测试（约 40 分钟）

`src-tauri/tests/e2e.rs`，11 条，真跑 ffmpeg、回读产物。找不到 ffmpeg 直接失败（不允许静默跳过）。

| # | 用例 | 断言 |
|---|---|---|
| 1 | mp4(h264+aac) → mkv（`-c copy`） | 产物可被 ffprobe 读出 h264 + aac，字节数接近源 |
| 2 | mp4 → gif（palettegen 链） | 产物帧数 > 1，首帧尺寸符合缩放预期 |
| 3 | png → avif（libsvtav1） | 产物被 `avif` 解复用器识别，宽高正确 |
| 4 | 有声视频 → m4a | 产物有 aac 流，时长差 < 0.2 s |
| 5 | 无声视频 → m4a | 任务以「无音轨」失败，不产出文件 |
| 6 | mp4 → mp3，质量 20 / 80 | 体积单调递增，`-b:a` 生效 |
| 7 | srt → ass / vtt / lrc | 回读产物，首行时间戳格式符合各自语法 |
| 8 | 视频 → ico | 产物魔数为 `00 00 01 00`，尺寸 ≤ 256 |
| 9 | 视频 → dv（pal-dv） | 产物 `dvvideo` + `pcm_s16le`，720×576 |
| 10 | 视频 → mxf（dnxhd） | 产物 `dnxhd` + 48 kHz `pcm_s24le` |
| 11 | 长转码中途取消 | 进程结束、残片被删、状态为「已取消」 |

可选第 12 条：真跑 2 秒素材，采样 `progress` 事件，断言百分比单调不减且终值 100。

**验收**：`cargo test` 含 11 条 e2e，总耗时 < 60 s。

## 5. 测试策略

三层，各自有明确边界：

1. **纯单测（不碰 IO）**：格式表完整性、能力解析、进度解析、兼容矩阵、参数构建。
   用快照 fixture 保证确定性。
2. **端到端**：真 spawn ffmpeg，回读产物。定位 ffmpeg 的规则与运行期一致，缺失即失败。
3. **手工验收**：安装包走完整流程（能装、能跑、能转、能卸）。

不使用「mock 掉进程」的做法——参数对不对只有真跑才知道。
